Weekly dengue admission forecasts for Bangladesh

Dengue hospital admissions, forecast 1-4 weeks ahead, with honest ranges.

DengueCast BD turns public DGHS reports into weekly forecasts for the country and its divisions. Every forecast comes with a range, and every claim is backed by a locked, public test on a season the models never saw.

    Who it helps, and how to use it

    The forecasts are free, public and updated weekly. Here is how different people can turn them into decisions.

    Hospital managers

    Plan beds, staff and IV fluids for the coming weeks.

    • Plan for the upper end of the 90% range, not the middle.
    • Watch the 2-4 week bands for your division.
    • Rising bands = start surge preparations early.

    Health planners

    Compare divisions and move resources before the peak.

    • Rank divisions by forecast next-week admissions.
    • Check the track record per division before trusting it.
    • Use the CSV files for your own reports.

    Researchers

    Reproduce every number and test better models fairly.

    • Locked plan (prereg-v1) and a leakage-free replay.
    • Add a model as one Python function.
    • Score it against the same baselines.

    Journalists & public

    Report what is coming without overclaiming.

    • Quote the range, not just one number.
    • These are reported hospital admissions, not infections.
    • Past accuracy is public; live accuracy is not yet scored.
    How to read a forecast

    One number is never the full story.

    Each forecast gives a middle estimate and two ranges. In the 2024 test, the true number fell inside the darker 50% range about half the time and inside the lighter 90% range most of the time, which is what honest ranges should do. Ranges get wider the further ahead you look: that is uncertainty, not a flaw.

    Simple rule: plan capacity for the top of the 90% range; expect the middle estimate.

    How it works

    Five steps, each automated and tested. The point is not a clever model; it is forecasts you can trust because nothing could leak from the future.

    Collect

    DGHS daily releases (2026) and the public Mendeley daily dataset (2022-2024), saved unchanged with SHA-256 hashes.

    Archive with time

    Every value records when it became known. Code reads data only "as of" a moment, never later.

    Clean by rules

    Epi weeks, incomplete weeks left missing (never guessed), past-only outlier checks.

    Forecast

    Baselines, a time-series model (ARIMA), a machine-learning model (LightGBM) and their ensemble.

    Score honestly

    Weekly replay, weighted interval score, coverage, bootstrap intervals, verdicts set in advance.

    Plan locked before testingGit tag prereg-v1 was pushed before any 2024 data was loaded; the test ran once.

    No future leakageA forecast from the full archive equals one from an archive cut at forecast time; an injected leak makes the tests fail.

    Nothing rewrittenThe archive and published forecasts are append-only, enforced in CI on every push.

    Weekly live run

    Enter that week's 7 DGHS releases in data/manual/daily_releases.csv (rows must add up to the stated total), then the forecast workflow publishes every Saturday 22:30 BDT.

    Rules for contributors

    Never invent data; read only through get_data(as_of); never edit published forecasts; log plan changes in docs/DEVIATIONS.md.

    Limits and data quality

    What these forecasts can and cannot tell you.

    • Targets are hospital admissions reported by DGHS, not infections. Not a clinical tool.
    • Only one season (2024) is a true test; 2023 results were used for tuning and are optimistic.
    • The 2022-2024 data has no separate Dhaka city corporations and no national series: national = sum of the eight divisions.
    • The first live forecast (24 Oct 2026) was published late and flagged late: true; it was never back-dated.
    • Its inputs were transcribed from newspaper reprints; the 20 Oct release disagrees across sources, so Rajshahi and Dhaka were not forecast that week.
    • The live forecast uses the simple persistence model; the stronger ensemble is evaluated in the backtest.
    • No weather or population data yet; serotype shifts and immunity are not in public data.
    • Division level is too coarse to target mosquito control within cities. Live accuracy cannot be claimed until forecasts are scored.
